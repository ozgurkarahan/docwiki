# F3 gate - every chantier in scope (paired A/B)

Decision record of the words and meaning search plan (slice S8, feature F3). Gate A failed
(`2026-11-01-gate-a.md`), so the plan continues without the semantic lane: S7 (isolated
evaluation environment) -> S8 (F3) -> S9. This file states the criteria **before** the paid run
that judges them; the results are appended below the line, pass or fail.

## Question

When a question names or implies several chantiers, does `answer_context` reporting `coverage`
and `gaps` per chantier, together with the Researcher's per-chantier routine
(`get_index('hubs/chantiers')`, then `answer_context(within=...)`, 4 targeted calls at most),
bring back the cross-chantier answers the Researcher misses today, without new failures elsewhere?

## Arms (same day, same release, same question files)

- **Reference**: production. MCP with `DOCWIKI_ANSWER_CONTEXT_COVERAGE=off`, production
  Researcher agent version (current instructions).
- **F3**: isolated evaluation environment (S7). Same image and release, MCP with
  `DOCWIKI_ANSWER_CONTEXT_COVERAGE=on`, evaluation Researcher agent version identical to
  production except the MCP connection and the S8 instructions.
- The two arms run back to back; the release id recorded by both result files must be the same.
  Production is not changed during the run.
- A question **passes** when `answer_accuracy == 1` (the runner's deterministic metric; for
  `abstain=true`, abstention accuracy). Every question whose verdict differs between the arms
  (discordant) is replayed **2 more times per arm**; its verdict per arm is the majority of the
  3 runs. Concordant questions are not replayed.

## Offline checks (tests, before the paid run)

- Serialized `hits` of `answer_context` are byte-identical with the flag off and on.
- Flag off: the whole output is byte-identical to the behaviour before S8.
- `gaps` never reports a chantier as absent when a count query in its scope finds matches.

## Criteria (all must hold to switch F3 on in production)

1. Known cross-chantier dev failures `q017`, `q018`, `q029`, `q030`: **at least 2 of 4** pass in
   the F3 arm.
2. Blind decision set (`retrieval-blind.jsonl`, sha256 in `retrieval-blind.sha256`), its
   6 `multi-chantier` questions only, run through `evals/run.py` as a non-dev split (aggregates
   only): F3 arm passes **at least reference + 2**.
3. Dev split (32 questions): net gain `gained - lost` **> 0**.
4. Confirmed new failures (passed in reference, failed in F3 after replays) **<= 1** on dev, and
   **0** among: questions that name at most one chantier (computed by the S8 detector, listed in
   the results), `numeric`, `restricted`, `injection`.
5. Median latency of the F3 arm **<= reference + 5 s** on dev. The p95 of the number of tool calls
   per question is published for both arms (no threshold).

If any criterion fails, F3 stays off in production (flag `off`) and the result is published in
the CHANGELOG; the code may stay, as it does not change `hits`.
