# F3 v2 gate - fan-out per chantier (paired A/B)

Second attempt at feature F3 (slice S8), after the first F3 gate failed
(`2026-11-01-f3-coverage.md`). This file states the criteria **before** the paid run that judges
them; the results are appended below the line, pass or fail.

## What changed since the first gate (designed after looking at it)

The four targeted dev failures (q017, q018, q029, q030) name no chantier: a supplier's shortage,
"the windows". F3 v1 only reported chantiers already among the first candidates or named in the
question, so the chantier crowded out of the ranking (the school) never appeared. F3 v2: when a
question names no chantier, or several, `answer_context` also searches each chantier on its own
and adds, per chantier, `in_scope_matches` and `top` (identifiers of its best match, no text) to
`coverage`, with a `coverage_hint`; `hits` stay byte-identical. The Researcher instructions say:
check each chantier that may be concerned with `within` (at most 4 calls), then answer per
chantier. **Overfitting risk:** the change was designed while looking at these four dev
questions; criteria 2 to 4 (blind set, the 28 other dev questions) guard against it, and the
result must not be read as a held-out estimate on the four.

## Arms (same day, same release, same question files)

As in the first F3 gate: **reference** = production (MCP flag off, production Researcher);
**F3 v2** = evaluation MCP app with the v2 image and the flag on, evaluation Researcher with the v2
instructions. Same release id recorded by every result file; production is not changed. A
question passes when `answer_accuracy == 1` (abstention accuracy for `abstain=true`). Every
discordant question is replayed 2 more times per arm; verdict = majority of 3.

## Criteria (all must hold to switch F3 on in production)

1. Known cross-chantier dev failures q017, q018, q029, q030: **at least 2 of 4** pass in F3 v2
   (after replays when discordant).
2. Blind multi-chantier subset (6 questions, aggregates only): F3 v2 passes **at least as many as
   the reference** (no loss). Changed from "reference + 2": the reference already passed 6 of 6
   in the first gate after replays, so +2 cannot be reached; this is stated before the run.
3. Dev net gain `gained - lost` **> 0**.
4. Confirmed new failures **<= 1** on dev, and **0** among `numeric`, `restricted`, `injection`
   and the questions that name exactly one chantier (S8 detector).
5. Median latency of F3 v2 **<= reference + 5 s** on dev; p95 of tool calls published.

If any criterion fails, F3 stays off in production and the result is published.

**F3 v2 gate: FAIL** (criteria 1 and 3). F3 stays off in production. Observations, after the
fact: the per-chantier search made the agent check each chantier, which fixed q029 ("When are
the windows delivered?"), but on q017, q018 and q030 the answers still miss one date or one
chantier, and on q020 (a company contract question naming no chantier) it led away from the
answer: lexical scores cannot tell which chantiers a question really concerns, so the fan-out
fires on every question that names none.
