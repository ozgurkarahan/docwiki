# Spec changelog

The v1 documents in this folder are frozen. Clarifications and changes discovered while building
are recorded here; the code and `src/docwiki/contracts/CONTRACT.md` follow this changelog.

## v1.1

| Area | Change | Why |
|---|---|---|
| Links | Evidence links resolve in a **content namespace** where `evidence/` is mounted at the wiki root (the Quartz `content/` layout); `wiki/evidence` is reserved. | One link form for the site, the MCP server and local agents. |
| Releases | `release_id` hash = hash of the manifest **identity fields** (created_at, audience, run, inputs, versions), not of the whole manifest. | Pages embed the release id; hashing the whole manifest would be circular. |
| Releases | Per-source tables are stored as `tables/<source_id>/<table_id>.parquet` + `index.json`, queried through a locked-down, SELECT-only DuckDB. | Exact numbers with row ids for `query_table`. |
| Citations | New badge **`paraphrase`** for citations without a quote whose numbers match the source. | The four v1 badges had no honest label for paraphrases. |
| Gates | **G04** counts only quoted native-text/table citations (verified vs failed); paraphrases are reported separately. | Section markers carry no quotes by design. |
| Extraction | Content Understanding is used for **PDF and images only**; DOCX, PPTX, XLSX, CSV, EML, VTT and text are always parsed locally. | Stable paragraph/row/slide locators in every mode. |
| Injection | Sources flagged for injection never publish their original; sidecars replace the offending sentence with a visible placeholder; canaries come from `DOCWIKI_CANARIES` and the pack's `canaries.txt`; G08 scans every release file including the built site. | Verbatim evidence must not re-publish an attack. |
| MCP | Tool failures (forbidden, not found, invalid arguments, timeouts) are returned as normal results `{"ok": false, "error": {...}}`; missing principals still get HTTP 401. `tools/list` shows every DocWiki tool to any caller holding a DocWiki role (none without a role); every call is still role-checked before its arguments are validated, and each agent's `allowed_tools` keeps the operations tools out of the Researcher's model. | Any MCP tool error aborts the whole Foundry agent turn (identity spike). Agent Service caches one tool list per MCP connection and shares it between the agents using that connection: a role-filtered list from a Researcher turn hid the Librarian's operations tools for about 15 minutes (live deployment). |
| Identity | Per-agent **Entra agent identities**; MCP API app registration with app roles and v2 tokens; Container Apps built-in auth with `allowedApplications` = the agents' client IDs; project connection `RemoteTool` / `AgenticIdentityToken`; the role claim arrives as the long URI claim type. | Validated end to end by the identity spike — see ADR 0003. |
| State | Extra files under `work/state/`: `build-<audience>.json` (no-op detection), `hints/` (operator hints), `overlay-applied.json`. | Idempotent runs and auditable recompiles. |
| Site | Quartz pinned to **v4.5.2** (v5 links plugins with directory symlinks, which fail on Windows without elevated rights); system font stacks (no font downloads); the portal CSP allows `'unsafe-eval'` for Quartz's graph and explorer while still serving only self-hosted scripts. | Portable builds; documented trade-off. |
| Site | GitHub ignores the `CNAME` file for Actions-based Pages deployments: the custom domain is also set in the repository settings. | Platform behaviour. |
| Settings | New keys: `DOCWIKI_ROLE_CLAIM`, `DOCWIKI_READ_ROLE`, `DOCWIKI_OPERATE_ROLE`, `DOCWIKI_MCP_URL`, `DOCWIKI_AGENT_TIMEOUT_SECONDS`, `DOCWIKI_CANARIES`, `DOCWIKI_ORCHESTRATOR`, `DOCWIKI_SITE_BUILD`. | Configurable auth mapping, agents and publish behaviour. |
| Identities | One user-assigned managed identity **per workload** (jobs, mcp, portal) instead of one shared runtime identity; the mcp identity may write in `work/` only under `reports/`, `proposals/` and `state/overlay.yaml` (role-assignment condition) and may send to the ingest queue; the jobs identity holds Storage Queue Data Contributor on `ingest` — the only built-in role that can renew message visibility (it also allows sending, which the job never does). | Least privilege within the limits of built-in roles. |
| State | `work/state/domain-pack.json` records the domain pack (with the applied overlay) used by the last run, so the MCP server can validate a proposal before `decide_proposal` accepts it; invalid overlay entries are skipped one by one and reported as run warnings instead of failing every run. | One bad accepted proposal must never block all future ingests. |
| Quarantine | Quarantines record `retryable` and `attempts`. Transient failures (Content Understanding throttling, outages, network or auth errors; scratch hash mismatches) are retried on the next runs, up to 3 attempts; throttling and auth errors fail the run so the queue retries it. Run reports carry a `warnings` list. | Transient platform errors must not silently remove documents from the wiki. |
| Infra | `DOCWIKI_MCP_ALLOWED_CLIENT_IDS` / Bicep `mcpAllowedClientIds` carry the agents' client IDs into the built-in auth allowlist so later `azd provision` runs keep it; `DOCWIKI_MCP_BLOCKED_AGENTS` is an operator kill switch. | The allowlist is mandatory on Container Apps (ADR 0003). |
| Security | MCP validates the forwarded bearer token in easyauth mode; external ingress only after built-in auth is verified. The server checks the token itself (RS256 with the tenant's v2 signing keys, issuer, audience, `exp`/`nbf`, `azp`/`appid` allowlist) and takes the caller and roles from it; the principal header never adds roles. New keys `DOCWIKI_MCP_TENANT_ID`, `DOCWIKI_MCP_AUDIENCE`, `DOCWIKI_MCP_ALLOWED_CLIENT_IDS`, `DOCWIKI_MCP_TOKEN_VALIDATION` (`required` by default, `off` as a logged opt-out; without tenant or audience the server refuses to start). Bicep gives the `mcp` app external ingress only once its auth config is declared; on the first run the postprovision hook verifies built-in auth, sets the token settings and only then enables ingress; the postdeploy smoke test requires `platform.enabled` and a 401 to a forged principal header. | A forged `X-MS-CLIENT-PRINCIPAL` header was accepted whenever the built-in auth sidecar was missing (failed hook, auth disabled while troubleshooting), and the smoke test could not tell because the server answers 401 to unauthenticated calls by itself. |
| Models | Defaults: `fast` = gpt-5.4-mini, `smart` = gpt-5.5, **Global Standard** (Data Zone Standard available for data residency); preflight verifies availability and quota and never switches silently. | Current models available in all three allowed regions; Global Standard has the widest quota and the lowest list price. |
| Infra | The Event Grid system topic's Storage Queue Data Message Sender role is assigned on the **storage account** (not the `ingest` queue). An optional **network security perimeter** can enclose the storage account (`DOCWIKI_ALLOWED_IP_RANGES` for operator access); Event Grid cannot re-create its subscription inside an enforced perimeter. The disabled portal app is held at zero replicas. Jobs export traces and warnings to Application Insights and flush them before exiting. | Learned in the first live deployment (tenant policy, quiet logs, observable jobs). |
| Evidence | Text originals are published only when they pass the safe-content gate; Markdown originals are published as `original.txt` so they are never read as wiki or evidence pages. | An `original.md` failed the frontmatter gate and blocked the first fresh release. |
| Compile | Map and reduce calls get the same output budget as single-pass compiles (reduce calls no longer resend entity and flag lists). | A large CSV log was truncated at 16k output tokens and quarantined. |
| Run control | Deterministic failures (blocking gate or release-validation failures, invalid domain pack or overlay) acknowledge their queue messages and the worker exits 0 (the report says `failed` with the reason and gates); systemic and unexpected failures keep their messages for retry. Once a worker holds the lease, earlier reports still `running` are closed as `failed` ("abandoned"). The `mcp` app has a TCP startup probe allowing about 120 s for cold starts. | A failing gate was retried until the poison queue (four extra runs); a stopped execution left a report `running` forever; cold starts logged probe failures. |
| Agents | Agent calls use the SDK's retries for 408, 409, 429, 5xx and connection errors (`DOCWIKI_AGENT_MAX_RETRIES`, default 2), honouring `Retry-After`. | A Researcher question hit the deployment's rate limit four times in a row. |
| Injection | An injection is document text that tries to instruct or manipulate an AI system, model, assistant or automated agent. Text for human readers — disclaimers and banners (`FICTIONAL - NOT FOR OPERATIONAL USE`, `CONFIDENTIAL`), safety warnings, procedure steps, requests between people, form instructions — is never flagged (prompts `compile-v2`, `compile-map-v2`, `compile-reduce-v2`, compile stage version 4, `CompiledSource.injection_flags` description). A model flag on a block made only of words of the pack's `banner` is dropped and recorded in the compile warnings. `detect_injection` also matches sentences hard-wrapped over several lines. | The first live run withheld the fictional stamp of 10 of 37 sample sources and did not publish their originals. |
| Domain packs | `EntityType.title` is the **plural** display title (`Organisations`): used as is for entity indexes, the agent kit and related-section groups; a group with one member gets a naive singular (`Organisation`). | The two packs shipped at the time used plural titles; pluralising them again produced doubled plurals ending in "-ses" across the sample wiki. |
| Evals | The README scoreboard is a compact variant (headline metrics, cost per question, median latency); the full table with tokens, p95, versions and failed question ids stays in `evals/SCOREBOARD.md`. | Fourteen columns and long failure lists made the README hard to read; nothing is dropped, it moves one link away. |
| Infra | Portal access option `DOCWIKI_PORTAL_ACCESS` (`portalAccess`): `entra` (default, unchanged) or `public`, which serves the portal without sign-in and without an app registration, and only when the audience is `public` (Bicep `portalAnonymous`; any other audience keeps the portal without ingress). The postprovision hook registers nothing in public mode. | Lets a public-audience deployment be browsed on Azure Container Apps without GitHub Pages or Microsoft Graph access; the build it serves already excludes internal and restricted sources. |
| Studio | New optional Container App **DocWiki Studio** (`DOCWIKI_ENABLE_STUDIO`, package `docwiki.studio`, `docwiki studio`): upload into `raw/`, run timeline from run reports and source states, Researcher and Librarian questions through the Responses API with in-page approvals of `mcp_approval_request`. Own identity (Blob Data Contributor on `raw` with a delete-deny condition, readers on `work`, `releases` and the `ingest` queue, Azure AI User); one replica; Entra sign-in with ID tokens, assignment required and an application allow-list (`DOCWIKI_STUDIO_ALLOWED_PRINCIPALS`, written by the hook); ingress only after sign-in is verified; CSRF header and same-origin checks; daily question and upload limits. | The pipeline and the agents had no visible application: the only UI was the wiki. A separate app keeps the public portal read-only. |
| Infra | Opt-in `DOCWIKI_GRAPH_TOKEN_SOURCE=azd`: when continuous access evaluation refuses the Azure CLI token for Microsoft Graph, the hooks use the azd sign-in, after checking the same tenant and object ID. | A revoked CLI session blocked every `azd provision` until an interactive `az login`. |

## v1.2

Owner-approved amendment that replaces the sample world. Unlike v1.1, it is applied in place to the
documents of this folder: [README.md](README.md) (G8, glossary),
[domain-and-corpus.md](domain-and-corpus.md) (§2 to §5), [evals.md](evals.md) (§1),
[infra-ops-security.md](infra-ops-security.md) (§1) and the examples of [pipeline.md](pipeline.md)
and [wiki-contract.md](wiki-contract.md). The engine, its contracts and the wiki format do not
change.

| Area | Change | Why |
|---|---|---|
| Sample world | The public sample is a small fictional French construction company (domain pack `batiment`): one private household client and one chantier (a 30 m² house extension and a kitchen renovation in an invented town), with a builders' merchant, a window maker and an electrical subcontractor, from January to April 2026. Documents are in French and the wiki is in English (D10 unchanged); questions are asked in English and in French. The spec names roles only; names live in `samples/fiction/bible.yaml`. The planted scenarios (domain-and-corpus.md §3.2) include an abstain fact and a held-back planning revision whose supersession resolves a contradiction. It replaces the previous sample world. | A smaller demo, closer to everyday business documents (quotes, contract, invoices, e-mails), that is quicker to read, compile and evaluate. |
| Fiction rules | §2 checks new names against real construction companies, builders' merchants, window and joinery makers, electrical contractors, building-product brands, French communes and real people, and lists French trade terms (devis, avenant, retenue de garantie…) as generic; it no longer lists example brand names. | The checks follow the sample's industry. |
| Corpus layout | `samples/corpus/full/` holds 12 public documents and 1 restricted document (`full/restricted/`); `held-back/` holds 1 planning revision for the time-travel demo. There is no `quickstart/` subset and no quickstart flag in `MANIFEST.json`. Planted facts and the acceptance matrix live in `samples/fiction/PLANTED.md`. Supported formats that the sample does not use (CSV, PPTX, VTT, PNG, Markdown, text) stay covered by the extraction test fixtures. | The whole public corpus now has the size of the former 12-document subset. |
| Document contract | New domain-and-corpus.md §3.4: ASCII file names that pass the Studio upload check; devis and planning files start with their number and carry their indice; an anchored `doc_number_regex` and an `explicit_reference_regex` limited to "annule et remplace"; the avenant amends and never supersedes the contract; amounts without thousands separators; the canary in a paragraph of its own; restricted-only values; no golden answer resting on a photo. | Supersession, citation verification, injection containment and the restricted-exclusion check depend on these properties of the documents. |
| Domain packs | The second sample pack is removed; `domains/batiment` is the only shipped pack. Pack genericity is covered by the small test packs under `tests/`. | One fictional world everywhere; the engine has no pack-specific code, and the test packs exercise it with packs other than the sample's. |
| Golden set | Dev split of 12 to 20 questions covering the 12 categories; private holdout of about 5 questions (about a quarter of all questions, previously about 30 %), authored without the planted-facts notes or the dev set. English questions about French documents use only language-neutral `must_include` items (numbers with units, dates, document numbers, names from the bible); French words only for `lang: fr` questions. | Bounds that fit a 12-document corpus; a correct English answer must not need a French word to pass the deterministic check. |
| Evals | `baseline-long-context` puts all extracted text of the public documents of `full/` in the prompt (only if it fits the model budget). | The quickstart subset no longer exists. |
| Infra | Default `domainPack` is `batiment`. | The only shipped sample pack. |
| Examples | Examples in pipeline.md, wiki-contract.md, the README glossary and domain-and-corpus.md §4 use document numbers, roles or neutral terms, never proper names; two v1.1 rows above describe sample artefacts generically, with the same meaning. | Names live only in the bible; no normative change. |

## v1.3

Entries marked *proposed* follow [ADR 0007](../adr/0007-answers-in-the-wiki.md): they are built
and tested on the feature branch and wait for the owner's approval of the ADR; the others are
implemented.

| Area | Change | Why |
|---|---|---|
| Site | The home page shows, under its title, how the release was built (documents by status, release date, quality gate counts, run receipt and quality report links) and a collapsible "About DocWiki"; the home page's copy of the fictional notice is dropped when the site banner shows it. `docwiki-site.json` adds `documents`, `runId`, `runPage`, `qualityPage` and `quality` (gate counts), read from the release manifest, or passed by the pipeline's site stage for the staged release. | The notice appeared twice, and the quality report, the run receipt and About DocWiki sat at the very bottom of a long page. |
| Queries (*proposed*) | Filing inbox `work/inbox/queries/`: a reviewed Researcher answer becomes a contract query page there (`asked_by: human`, `approved_by: owner`, `sources` = every cited source, `sensitivity` = their highest tier, a "How this answer was produced" section, English text with quotations in their language; "Not found in the wiki." allowed with `sources: []`). The next run merges the inbox into `queries/` with the same citation checks as carried query pages; a non-empty inbox is never a no-op; the jobs identity deletes consumed items. | Closes the LLM-wiki loop: an agent's answer becomes a page people and agents can read, search and link. |
| Queries (*proposed*) | A build drops the whole query page when its audience excludes any cited source, and never lowers its tier; a superseded cited source adds a banner naming the current revision (withdrawn sources keep their warning banner). | D11: excluded sources leave no mention; answers must not look current when they are not. |
| Site (*proposed*) | "Ask this wiki" panel (amends D13): a static layout component on every page lists the filed questions, shows an answer with its citations, provenance badges, agent steps and provenance line; a citation opens the evidence beside the open drawer on wide screens (on narrower ones the drawer collapses to "Back to the answer"). Data `answers.json` emitted by the site build; DOM rendering only; no free-text input; state in `sessionStorage`. | The owner wants the agent inside the wiki; reviewed answers need no backend and no model spend for visitors. |
| Infra (*proposed*) | The Studio identity's role on `work` becomes the custom role "DocWiki Studio inbox writer" (blob read, write and create; no delete, move or container action; assignable in the resource group) with a condition (reads open; writes and creates only under `inbox/queries/`), replacing its Blob Data Reader assignment. Not Storage Blob Data Contributor: a condition never restricts its container actions (`containers/write`, `containers/delete`). An Event Grid subscription `inbox-to-ingest` sends BlobCreated events under `work/inbox/queries/` to the `ingest` queue. The Studio's "File to wiki" previews the page and files exactly what was reviewed, with a daily allowance (`DOCWIKI_STUDIO_DAILY_FILINGS`, default 20). | Owner-only filing from the Studio, run without a manual trigger; the Studio can never delete or rewrite the `work` container. |
| Evals (*proposed*) | Suggested questions never repeat golden questions; the golden set is evaluated before the first filing and after it, and both results are published. | The Researcher's search covers query pages. |

## v1.4

Corrections that make the spec tell what the code does (the code is right in each case), and the
retirement of GitHub Pages. Owner decisions of 2026-10-21 are recorded in `AGENTS.md`.

| Area | Change | Why |
|---|---|---|
| Hosting | GitHub Pages retired; the public demo is served from Azure Container Apps (the portal with a public-audience build). The `pages.yml` workflow, the committed `samples/wiki` and the custom domain are gone; there is one public repository. site.md section 4, infra-ops-security.md section 6, D13 and G8 follow. | One app on Azure instead of a second static host fed by a committed copy of the wiki. |
| MCP | mcp-and-agents.md section 1 (Authorization): the server validates the RS256 bearer token itself (issuer, audience, `exp`/`nbf`, `azp`/`appid` allow-list) and takes the caller and roles from it; the principal header never adds roles. | Matches v1.1 (Security) and `src/docwiki/mcp/auth.py`; the earlier text trusted the header. |
| MCP | The tool list is not filtered per role; the role is checked on every call (D9). The README and `docs/agents.md` no longer say the server hides tools. | Matches v1.1 (MCP): a role-filtered list from one agent turn hid the other agent's tools. |
| Identities | architecture.md sections 2 and 6: one user-assigned managed identity per workload (jobs, mcp, portal, studio), not one shared runtime identity. | Matches v1.1 (Identities, Studio). |
| Infra | infra-ops-security.md section 1: `deploymentSku` defaults to `GlobalStandard` (`DataZoneStandard` is the data-residency option); there are four images (job, mcp, portal, studio). | Matches `infra/main.bicep` and `docker/`. |

| Docs | The ADR index links ADR 0003. | It was the only unlinked ADR. |

## v1.5

Live ask: the Researcher answers visitors in the wiki's drawer ([ADR 0008](../adr/0008-one-experience-live-agent-in-the-wiki.md),
owner decision of 2026-10-21 in `AGENTS.md`).

| Area | Change | Why |
|---|---|---|
| Security | The invariant "no public endpoint calls an LLM" (architecture.md section 8, D13) is dropped. It is replaced by: a gateway in front of the Foundry project (an existing, shared API Management instance, passed in as a parameter) with a per-visitor rate, per-visitor and global token budgets and a daily cut-off; portal guards (body, question length, content type, same origin, one running question per visitor, a few in total, a per-visitor window); a fallback to the filed answers. | One experience: the agent lives in the wiki page. |
| Site | The drawer is always built and the client decides whether to show it; with the live ask it gets a question form (site.md section 7). ADR 0007's "no free-text input" and "visitors only see filed answers" are superseded. | Owner decision. |
| Portal | New `/api/ask/status`, `/api/ask` and `/api/ask/{job_id}` (`docwiki.portal.live_ask`), on only with `DOCWIKI_LIVE_ASK=1` and `DOCWIKI_FOUNDRY_PROJECT_ENDPOINT`. A live answer is `verified` only when every `[n]` of its text is an evidence sidecar path whose page exists in the served site; otherwise `unverified`, shown without citations. | Documents and model output are untrusted; the gate is deterministic. |
| Agents client | `AgentClient.ask(..., headers=...)` passes extra HTTP headers on every Responses API call of a question (the gateway reads `X-Visitor-IP`). | Per-visitor limits at the gateway. |
| Infra | Optional Bicep parameters `enableLiveAsk` and `liveAskEndpoint` (`DOCWIKI_ENABLE_LIVE_ASK`, `DOCWIKI_LIVE_ASK_ENDPOINT`) give the portal `DOCWIKI_LIVE_ASK=1` and `DOCWIKI_FOUNDRY_PROJECT_ENDPOINT`; the policy template `infra/apim/docwiki-live-ask-policy.xml` and [docs/live-ask.md](../live-ask.md) describe the gateway. | The gateway is not created by DocWiki and never committed. |
