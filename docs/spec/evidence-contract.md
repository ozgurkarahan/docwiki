# Evidence contract

## 1. ExtractedDoc

Every extractor adapter returns the same structure (stored as JSON in the extract artifact):

```json
{
  "schema": 1,
  "source_id": "src-…",
  "source_path": "relative/path.ext",
  "source_hash": "sha256:…",
  "media_type": "application/pdf",
  "lang": "en",
  "title_hint": "string or null",
  "metadata": {"doc_number": null, "revision": null, "authored": null, "page_count": 12},
  "blocks": [Block, …],
  "tables": [Table, …],
  "figures": [Figure, …],
  "extraction": {"adapter": "local|content-understanding", "adapter_version": "…",
                 "analyzer": "prebuilt-layout|…|null", "model": null, "warnings": []}
}
```

**Block**

```json
{"id": "b0042", "kind": "heading|paragraph|list|table-ref|figure-ref|slide|email-header|email-body|cue|ocr-line|note",
 "text": "…", "level": null, "locator": Locator, "provenance": "native-text|ocr|deterministic-table|model-description",
 "lang": "en", "confidence": null}
```

Block ids are `b` + 4-digit sequence in reading order, stable for a given input and adapter version.

**Table** (always produced by deterministic parsing for XLSX/CSV; by layout analysis for PDF/DOCX/PPTX)

```json
{"id": "t03", "locator": Locator, "provenance": "deterministic-table|native-text|ocr",
 "columns": ["…"], "rows": [{"row_id": "r0012", "cells": ["…"]}], "artifact": "tables/t03.parquet"}
```

Tables are also written as Parquet (or CSV) artifacts so DuckDB can query them with row ids.

**Figure**

```json
{"id": "f02", "locator": Locator, "image": "figures/f02.png", "caption": "…|null",
 "description": "…|null", "description_provenance": "model-description|null", "bbox": [x0, y0, x1, y1]}
```

## 2. Locators

| Format | Locator fields | `locator_key` | Label |
|---|---|---|---|
| PDF (text or scanned) | `page` (1-based), optional `bbox` | `p0003` | `p. 3` |
| DOCX | `paragraph` (1-based index of body paragraphs) or `table` + `row` range | `para-0042` / `tbl-02-r0003-r0007` | `¶ 42` / `table 2, rows 3–7` |
| XLSX | `sheet` (name), `row_start`, `row_end` (1-based, header = row 1), optional `cols` | `sheet-<slug>-r0012-r0020` | `sheet "Plan", rows 12–20` |
| CSV | `row_start`, `row_end` (header = row 1) | `r0012-r0020` | `rows 12–20` |
| PPTX | `slide` (1-based), optional `shape` | `slide-05` | `slide 5` |
| EML | `part` (`headers`, `body`, `attachment:<name>`), optional `line` range | `msg-body-l0010-l0018` | `message body, lines 10–18` |
| VTT | `cue_start`, `cue_end` (HH:MM:SS) | `cue-00-03-15` | `03:15–03:42` |
| Image (scan/photo) | `page` = 1, `bbox` | `img-b07` | `region 7` |
| MD/TXT | `line_start`, `line_end` | `l0010-l0018` | `lines 10–18` |

A locator always resolves to exactly one sidecar file.

## 3. Provenance types

| Provenance | Meaning | Can earn "✓ quote verified" |
|---|---|---|
| `native-text` | Text present in the file's own text layer (PDF text, DOCX runs, PPTX text, EML, VTT, MD) | Yes |
| `deterministic-table` | Cell values parsed from XLSX/CSV or a deterministic table parser | Yes (as `table`) |
| `ocr` | Text recognised from pixels (scans, images) | No — badge `OCR`, with confidence and crop |
| `model-description` | Text generated by a model to describe a figure, chart or image | No — badge `generated description` |

## 4. Quote verification

Compilation outputs facts with citations `{block_id, quote}` (quote optional for paraphrases).
Verification is deterministic:

1. Normalise both quote and block text: Unicode NFKC, case-fold, straight quotes, collapse
   whitespace, remove soft hyphens.
2. The quote must be a substring of the normalised text of the cited block (or of the
   concatenation of the cited blocks when several are cited).
3. Numbers in a fact (with units) must appear in at least one cited block or table cell.
4. Table citations must reference existing `row_id`s; cell values cited must match exactly after
   normalisation.

Results per citation: `verified`, `unverified-paraphrase` (no quote supplied, numbers match),
`failed`. `failed` citations are removed and the fact is dropped or re-asked once; gates count them.

## 5. Evidence sidecars

For every cited locator the build writes `evidence/<source_id>/<locator_key>.md` (+ assets):

```
evidence/<source_id>/
  index.md                     # the document page: title, wiki page and original links, page
                               # images (only with a published original), full text with tables,
                               # then the cited locators (v1.7, ADR 0010)
  original.<ext>               # public sample builds only: copy of the original file
  p0003.md                     # PDF page sidecar
  img/p0003.png                # rendered page image (150 dpi) with highlight boxes for cited bboxes
  sheet-plan-r0012-r0020.md    # XLSX rows rendered as a Markdown table with "Row 12" … headings
  …
```

Sidecar page content:

- frontmatter `{id: "evidence:<source_id>:<locator_key>", type: "evidence", source_id, locator,
  provenance, sensitivity}`;
- a heading with the locator label, a link back to the source page and to `original.<ext>` (with
  `#page=N` for PDFs) when the original is published;
- the verbatim block text (native-text) or table rows (deterministic-table) with row headings,
  or the image crop (OCR) with recognised text and confidence, or the figure with its generated
  description clearly labelled;
- the provenance badge.

Sidecars inherit the sensitivity of their source and are excluded with it.

## 6. Adapter requirements

- **Local adapter**: PDF via pypdfium2 page by page (text + page render for sidecars; pages with no
  text layer are marked `needs-ocr` and, in local mode without OCR, produce an `ocr` block with
  empty text and a warning); DOCX via python-docx (paragraph and table indices); XLSX via openpyxl
  (values, not formulas; merged cells expanded); CSV via the `csv` module (sniffed dialect,
  UTF-8 with BOM handling); PPTX via python-pptx (slide text, notes, tables); EML via `email`
  (headers, text/plain preferred, HTML converted to text safely, attachments listed);
  VTT parsed by cue; MD/TXT by line.
- **Content Understanding adapter**: `prebuilt-layout` by default for PDF and images only
  (markdown + layout + tables + figure regions with page numbers and bounding boxes); figure
  descriptions are produced by DocWiki's own `fast` model call on figure crops (provenance
  `model-description`); `prebuilt-documentSearch` and `prebuilt-audioSearch` are opt-in per
  domain pack. DOCX, PPTX, XLSX, CSV, EML, VTT and text are **always** parsed by the local
  deterministic parsers, even in Azure mode.
- **Parity tests**: both adapters run on the same fixtures; tests compare block counts per
  locator, table cells and locators (text may differ in whitespace).
- **Recorded fixtures**: Content Understanding responses are recorded for the fixtures and
  replayed in CI.
