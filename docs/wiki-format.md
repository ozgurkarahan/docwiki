# The wiki format

A DocWiki wiki is a folder of UTF-8 Markdown files with YAML frontmatter, plus a few machine files.
It renders on GitHub, in Quartz, in Obsidian and in VS Code, and an agent can navigate it with
nothing but file reads. This page is a guided tour; the normative definitions are the
[wiki contract](spec/wiki-contract.md), the [evidence contract](spec/evidence-contract.md) and
[`CONTRACT.md`](../src/docwiki/contracts/CONTRACT.md).

## Layout

```text
wiki/
  index.md                 home: purpose, how to navigate, categories, topics, counts, recent changes
  AGENTS.md                how agents should use this wiki
  llms.txt                 llmstxt.org index of the most useful pages
  log.md                   append-only change log
  glossary.md              terms, definitions, multilingual synonyms
  catalog.json             machine catalog: pages, typed edges, sources, glossary
  sources/                 one page per source document, plus index.md
  entities/<type>/         one page per registry entity, plus per-type and global indexes
  topics/                  curated multi-source syntheses, plus index.md
  queries/                 research answers filed back into the wiki
  _meta/quality.md         gate results of this release
  _meta/runs/<run_id>.md   run receipt: durations, cache hits, tokens, costs, versions
  .agents/skills/  .claude/skills/  .github/skills/    identical Agent Skills
```

Next to `wiki/`, each release holds `evidence/` (the sidecars), `tables/` (one Parquet file per
extracted table), `search.db` and `manifest.json`; see [architecture](architecture.md#release-lifecycle).

## Page types

| Type | Id | Path | What it holds |
|---|---|---|---|
| source | `src-` + 12 hex of the raw path hash | `sources/<slug>.md` | One document: summary, key facts, compiled sections with preserved tables, figures, related pages |
| entity | `<type>:<key>`, e.g. `building-element:baie-f1` | `entities/<type>/<key>.md` | A registry object of the domain pack: facts and a dated timeline aggregated from every source that mentions it |
| topic | `topic:<slug>` | `topics/<slug>.md` | A synthesis from the pack's closed topic catalog: overview, thematic sections, contradictions, superseded information |
| query | `query:<yyyy-mm-dd>-<slug>` | `queries/<date>-<slug>.md` | A reviewed research answer filed back into the wiki (`docwiki file-answer`): the answer with cited evidence, "How this answer was produced", the question and `approved_by: owner` |
| index, glossary, log, meta | `index:<scope>`, `glossary`, `log`, `meta:<name>` | `index.md`, `<scope>/index.md`, `glossary.md`, `log.md`, `AGENTS.md`, `_meta/…` | Navigation and bookkeeping, generated by code |

Identifiers, slugs and paths are computed by code, never by a model: a source slug is the ASCII
kebab-case of the file name, and paths must match `^[a-z0-9][a-z0-9\-/._]*$` (gate G09). A new
revision of a document is a new source; its page links the revision it replaces.

Query pages from earlier releases are carried into every new release, re-cited against the new
evidence (current source titles, locator labels and badges; the page tier follows its sources); a
citation whose source was withdrawn is removed and the page gets a warning banner, a cited source
that was superseded adds a banner naming its current revision, a page whose sources are above the
audience of a build is left out of that build, and a page that would still fail the release checks
is left out with a warning and a `withdraw` log entry. Newly filed answers wait in
`work/inbox/queries/` until the next run ([agents](agents.md#filing-an-answer-into-the-wiki)).

## Frontmatter

Every page starts with YAML frontmatter. Common fields:

| Field | Meaning |
|---|---|
| `id`, `type`, `title` | Identity of the page |
| `summary` | One line, used by indexes, `llms.txt` and search |
| `lang` | Always `en`: the wiki is written in English, quotes stay in their original language |
| `sensitivity` | `public`, `internal` or `restricted`: the highest tier of the page's sources |
| `updated` | Release date of the last change |
| `tags` | Lower-case, de-duplicated, sorted |
| `docwiki` | `{schema: 1, release: <release_id>}` |

Source pages add `source_id`, `source_path`, `source_hash`, `media_type`, `doc_type`, `category`,
`doc_number`, `revision`, `status` (`current`, `superseded`, `withdrawn`), `supersedes`,
`superseded_by`, `original_lang`, `pages`, `entities`, `topics`, `authority` (1 to 10, from the
domain pack) and `extraction` (adapter, version, mix of provenance types). Entity pages add
`entity_type`, `key`, `aliases` (with language tags) and `sources`. Topic pages add `topic_slug`,
`sources`, `confidence`, `contradictions` and `superseded_claims`. Query pages add `question`,
`asked_by`, `sources` and `approved_by`.

The full page also has a section per theme (here `## Window delivery` and `## Masonry progress`),
`## Sources consulted` (status and authority of each source), `## Related` and a generated
backlinks block. Notice what the format guarantees:

- The contradiction is **shown, not resolved silently**: both claims, both citations, their
  authority, and the resolution rule of the domain pack, which here favours the minutes
  (authority 7) over the planning (authority 4).
- Superseded information is kept but **separated** from current information, with the
  superseding source: the delivery date of indice A of the planning (2026-03-30) is listed under
  `## Superseded information`, next to its replacement.
- Every claim has a footnote; every footnote opens the exact paragraph, page or rows it rests on.

## Citations and provenance badges

Footnote labels are `c1`, `c2`, … in order of first use, and every definition has one form:

```text
[^c3]: [<source title> — <locator label>](../evidence/<source_id>/<locator_key>.md) · <badge>
```

| Badge | Provenance | Meaning |
|---|---|---|
| `✓ quote verified` | `native-text` | The model's quote was found in the cited block by code (Unicode NFKC, case-folded, quotes and whitespace normalised, soft hyphens removed), and every number with its unit appears in the cited blocks |
| `paraphrase` | `native-text` | No quote, but the numbers match the source; honest label for a faithful paraphrase |
| `table` | `deterministic-table` | Cell values parsed by code from a spreadsheet, CSV or table, cited by row id; never retyped by a model |
| `OCR` | `ocr` | Text recognised from pixels (scans, photos), such as the handwritten remark on a scanned delivery note; may contain recognition errors |
| `generated description` | `model-description` | A model's description of a figure; never a quote of the document |

Citations that fail verification are removed and the fact is dropped or re-asked once. Gate G04
blocks a release when fewer than 95 % of quoted native-text and table citations verify (warning
below 98 %).

## Evidence sidecars

Every cited locator gets one sidecar page, `evidence/<source_id>/<locator_key>.md`, published with
the release. It shows the cited content next to a link back to the source page and, for the public
sample, to the original file.

| Format | Locator key | Label | The sidecar shows |
|---|---|---|---|
| PDF | `p0003` | `p. 3` | The rendered page (150 dpi) with highlight boxes and the verbatim text |
| DOCX | `para-0042`, `tbl-02-r0003-r0007` | `¶ 42`, `table 2, rows 3–7` | The paragraph, or the table rows |
| XLSX | `sheet-planning-r0012-r0020` | `sheet "Planning", rows 12–20` | The rows under `## Row N` headings |
| CSV | `r0012-r0020` | `rows 12–20` | The rows under `## Row N` headings |
| PPTX | `slide-05` | `slide 5` | The slide text, tables and notes |
| EML | `msg-body-l0010-l0018` | `message body, lines 10–18` | The message lines |
| VTT | `cue-00-03-15` | `03:15–03:42` | The transcript cue |
| Image | `img-b07` | `region 7` | The OCR crop and its recognised text |
| MD, TXT | `l0010-l0018` | `lines 10–18` | The lines |

addressed to AI assistants is replaced by a visible placeholder pointing to the quality report.

## Links and anchors

- Internal links are **relative Markdown links with the `.md` extension**, so they work on GitHub,
  in Quartz, Obsidian and VS Code. The canonical wiki has no `[[wikilinks]]`;
  `docwiki export obsidian --out <vault>` writes a copy that uses them.
- Links resolve in a **content namespace** where `evidence/` is mounted at the wiki root, exactly
  as in the Quartz `content/` folder. The site, the MCP server and agents that read through it
  resolve evidence links; browsing a raw release folder on GitHub does not.
- Anchors are headings with simple ASCII text (`## Row 12` → `#row-12`), so every renderer derives
  the same slug. Gate G02 checks that every link and anchor resolves.
- No raw HTML, except the two generated comments that delimit the backlinks block. No links to
  hosts outside the wiki, except the published originals of the public sample.

## Supersession, contradiction and withdrawal

- **Supersession.** A later revision of the same document number, or a source that explicitly
  replaces another, supersedes it. The old source keeps its page with `status: superseded` and a
  banner linking the replacement; topic pages give the current claim first.
- **Contradiction.** Two current sources disagree. Both claims are shown with citations, authority
  and dates, and the pack's resolution rule (by default authority, then recency) is stated.
- **Withdrawal.** A raw file is deleted. Its page disappears, a `withdraw` entry is appended to the
  log, dependent pages are rebuilt, and query pages that cited it get a warning banner.

## Sensitivity and audiences

Each source gets a tier from the domain pack (`public`, `internal`, `restricted`) by path glob or
document type. A build targets one audience, and a source above it is excluded completely: no
page, no mention, no evidence, no catalog entry, no search row (gate G07). A page that combines
sources has the highest tier among them, and pages never mix tiers the audience may not see.

## Machine files

| File | Content |
|---|---|
| `index.md` | What the wiki covers, how to navigate (start here → categories → topics → entities → glossary → log), counts, topics, the last 10 log entries |
| `AGENTS.md` | Page types, navigation strategy, citation rules, contradiction and supersession handling, skills, MCP tools and the rule that documents are data. See [skills](skills.md) |
| `llms.txt` | [llmstxt.org](https://llmstxt.org/) index: `## Start here`, `## Topics`, `## Entities`, `## Sources` |
| `log.md` | Append-only entries `## [YYYY-MM-DD] <ingest, update, supersede, withdraw, topic, query or lint> \| <title>` with links to the affected pages |
| `glossary.md` | One section per term: definition, synonyms per language, related pages. Search expands queries with these synonyms |
| `catalog.json` | Every page (id, type, path, title, summary, sensitivity, status, tags, entities, topics, sources) and typed edges: `mentions`, `supersedes`, `cites`, `related`, `topic-of` |
| `search.db` | SQLite FTS5 with one row per page section **and** one row per extracted source block, so details that compilation left out stay findable; BM25 ranking with a pure-Python fallback |

```markdown
# Chantier Moreau mock wiki

> Hand-made, fictional mock release of the DocWiki sample (CC BY 4.0) about a small building job. Every fact is cited to an evidence sidecar.

## Start here

- [Agent guide](AGENTS.md): page types, citation rules, skills and tools
- [Glossary](glossary.md): acronyms and multilingual synonyms
```

## Content safety

Applied by code after every model call and checked again by the gates:

- HTML tags, comments, scripts, `javascript:` and `data:` URLs and links to unknown hosts are
  removed; images from external URLs cannot be created (gate G05).
- Text that addresses the reader as an AI system ("ignore previous instructions", tool-call
  syntax, requests to exfiltrate) is dropped from compiled pages, the source fact is kept, and an
  injection proposal is filed for a human.
- Canary tokens must never reach `AGENTS.md`, skills, indexes, evidence or the built site (gate
  G08).

## Check a release

```bash
uv run docwiki lint --release samples/fixtures/mock-release
```

`docwiki lint` validates frontmatter, links and anchors, citations, sidecars, audience, canaries,
paths, supersession, tags, orphans and skills, and prints one line per finding with its gate.
