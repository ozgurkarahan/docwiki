A small, hand-made DocWiki release in the exact storage layout of `docs/spec/architecture.md` §3.
Other lanes (MCP server, site, infra, evals) build and test against it before the pipeline exists.
It passes `validate_release` with zero violations.

It tells one story of the sample world (`samples/fiction/bible.yaml`, domain pack `batiment`): the
window maker VanArsdel Menuiseries postpones the delivery of the windows of the extension from
2026-03-30 to 2026-04-20, so the schedule PLN-2026-003 indice B supersedes indice A. Three sources,
one per evidence kind:

| Source id | Original | Evidence kind | Role |
| --- | --- | --- | --- |
| `src-c6436ec50050` | `planning/PLN-2026-003_indice-A_planning-et-suivi-des-achats.pdf` | PDF page: native text and page image | schedule indice A, superseded |
| `src-86eabe3d6d0d` | `planning/PLN-2026-003_indice-B_planning-et-suivi-des-achats.xlsx` | XLSX rows and the tables `t01` (sheet Planning) and `t02` (sheet Achats) | schedule indice B, current |
| `src-165f1d3a109c` | `chantier/2026-03-24_compte-rendu-de-chantier-n3.docx` | DOCX paragraphs | site meeting minutes n°3, current |

The sample corpus keeps indice A as a workbook. The fixture shows it as a printed PDF page so that
three sources are enough to cover the three evidence kinds. The workbook cells of indice B and the
paragraphs of the minutes come from the sample corpus; the page text of indice A is a short print.

The pages exercise: a supersession pair, a topic with **Contradictions** (walls at 70 % in the
minutes of 2026-03-24, authority 7, against 100 % in indice B, authority 4) and **Superseded
information** (the delivery date of the windows), French quotes in an English wiki, glossary
synonyms in French and English, two Parquet tables and one filed answer in `queries/`.


Source ids come from `docwiki.contracts.ids.source_id_for(source_path)` and the content hashes are
deterministic stand-ins (`sha256("mock-release:" + source_path)`); `build_fixture.py` checks the ids.

## Use it

```python
from docwiki.release import ReleaseReader

reader = ReleaseReader.open("samples/fixtures/mock-release")   # follows releases/current.json
reader.read_page("topic:schedule-and-window-delivery")
reader.resolve_evidence("src-86eabe3d6d0d", "sheet-planning-r0006-r0009")
reader.query_table("src-86eabe3d6d0d", "SELECT row_id, tache, debut FROM t01 WHERE lot = '5'")
with reader.open_search() as index:
    index.search("date de livraison des fenêtres")
```

## Rebuild

The Markdown is written by hand. `build_fixture.py` regenerates the page image, the Parquet tables,
both `catalog.json` copies, `search.db`, `manifest.json` and `current.json`, then validates:

```powershell
uv run python samples/fixtures/mock-release/build_fixture.py            # in place
uv run python samples/fixtures/mock-release/build_fixture.py --out DIR  # into a copy
```

Edit Markdown, rebuild, and commit the regenerated files together. The release id is derived from
the manifest identity in `build_fixture.py`; if you change the identity (sources, versions, dates),
the script reports the new id and every page stamp (`docwiki.release`) must be updated.
